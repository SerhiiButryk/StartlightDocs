## Retention of ViewModel in Activity during config changes

Let's find out how Android keeps ViewModel instances during Activity recreation. Let's start with a question - **Where does an instance of ViewModel get stored exactly?**

As an example we take a look at this snippet:

```kotlin

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            AppUI()
        }
    }
}

@Composable
fun AppUI(modifier: Modifier = Modifier) {

    val viewModel = viewModel<AppViewModel>()

    AppTheme {
        Scaffold(modifier = Modifier.fillMaxSize()) { innerPadding ->
            Content(
                modifier = Modifier.padding(innerPadding),
                viewModel = viewModel,
            )
        }
    }
}
```

But what is ViewModelStoreOwner? Here it is:

```kotlin

public open class ViewModelStore { 

    private val map = mutableMapOf<String, ViewModel>()

(...)

    public fun put(key: String, viewModel: ViewModel) {
        val oldViewModel = map.put(key, viewModel)
        oldViewModel?.clear()
    }

(...)

    public operator fun get(key: String): ViewModel? {
        return map[key]
    }

(...)

}
```

No magic it is just a map which actually stores instances of ViewModel that you use in the specific Activity instance. Okay that's fine. But map should be destroyed when Activity is destroyed, shouldn't it? 

That's right! But there is another bit here! There is always a ViewModelStoreOwner which actually owns the ViewModelStoreOwner. If you look through the ViewModelStoreOwner interface you'll see the comment - "A responsibility of an implementation of this interface is to retain owned ViewModelStore during the configuration changes". So who is the implementer? The implementer is our ComponentActivity class.

Let's see what it is doing:

```kotlin

open class ComponentActivity() : 
(...)
ViewModelStoreOwner
{ 
(...)

// OUR ViewModelStore IMPLEMENTATION
private var _viewModelStore: ViewModelStore? = null

(...)

// Special Activity callback
final override fun onRetainNonConfigurationInstance(): Any? {
        // Maintain backward compatibility.
        val custom = onRetainCustomNonConfigurationInstance()
        var viewModelStore = _viewModelStore
        
        (...)

        // OUR ViewModelStore instance gets wrapped with 'NonConfigurationInstances' instance
        val nci = NonConfigurationInstances()
        nci.custom = custom
        nci.viewModelStore = viewModelStore
        return nci
    }

}

(...)

// This is where OUR ViewModelStore instance gets restored
private fun ensureViewModelStore() {
        if (_viewModelStore == null) {
            val nc = lastNonConfigurationInstance as NonConfigurationInstances?
            if (nc != null) {
                // Restore the ViewModelStore from NonConfigurationInstances
                _viewModelStore = nc.viewModelStore
            }
            if (_viewModelStore == null) {
                _viewModelStore = ViewModelStore()
            }
        }
    }

(...)
```

The core of ViewModel retention is **onRetainNonConfigurationInstance** call. It turns out that an object which is returned by **onRetainNonConfigurationInstance** is not destroyed but saved by the Android OS. 

Let's dig deeper into this.

1. The ActivityThread class calls **performDestroyActivity** when activity is going to be destroyed.

2. The **performDestroyActivity** calls **retainNonConfigurationInstances** on our application Activity instance.

3. The result of this call gets saved in **lastNonConfigurationInstances** of **ActivityClientRecord**

4. The **ActivityClientRecord** is a wrapper which holds a specific Activity instance and some other info.

5. The ActivityThread keeps **ActivityClientRecord** object in a map.

6. After a new activity is created, the ActivityThread class gives **lastNonConfigurationInstances** back to the new Activity.

# Summary

1. ViewModel is retained using special **NonConfigurationInstances** wrapper class.

2. The ActivityThread class holds the actual instance of **NonConfigurationInstances** class.

3. So the ActivityThread class is the point where ViewModel gets stored by Android OS.

4. The ActivityThread class gives the instance of **NonConfigurationInstances** to the newly created Activity.
